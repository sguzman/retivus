# Linux release candidate (not published)

Run `cargo build --locked --release --features anki-backend --bin retivus`, then `bash scripts/package-linux.sh dist`. The candidate contains the binary, license, Anki attribution, original MIT notice, Retivus source snapshot, resolved Cargo.lock, exact commit/Git pin provenance manifest, desktop entry and local-prefix install/uninstall scripts. To include additional source snapshots in a local candidate, check out the exact Anki and rust-url commits recorded in `Cargo.lock`, and set `RETIVUS_ANKI_SOURCE_DIR` and `RETIVUS_RUST_URL_SOURCE_DIR` to their paths before packaging. Both must be supplied together; mismatched or modified checkouts are rejected. CI always includes both pinned snapshots.

The [candidate CI workflow](../.github/workflows/linux-candidate.yml) builds and checksums the archive, installs it into an isolated home **including AGPL, pinned Anki attribution, original MIT provenance and README**, launches a real X11 window, repeats installation, and uninstalls only when the managed binary, desktop entry and notice checksums match. The workflow also verifies that unmanaged binaries and existing notices cannot be overwritten. The pinned lockfile is committed, and the release-candidate archive retains it for independent inspection. A fast [installer safety contract](../.github/workflows/installer-contract.yml) additionally tests checksum-guarded upgrades, legacy migration, edited-license refusal, symlinked directories, unmanaged-file protection and unchanged personal study data without building the GUI.

**Not accepted:** the exact lockfile from the earlier green candidate workflow has been committed (6b1a3e5), and official Anki Desktop package interchange passed separately (CI 41368266062). Installer/notice hardening passed [release candidate CI 41374768777](https://github.com/sguzman/retivus/actions/runs/41374768777); the symlink/recovery contract passed [CI 41467012527](https://github.com/sguzman/retivus/actions/runs/41467012527). The CI candidate now bundles exact pinned Anki and rust-url tracked Git source snapshots and documents their revisions. This is **not** a corresponding-source compliance certification: excluded Git submodules, registry crate sources, build-tool scripts and all required third-party notices still need distribution review. Full corresponding-source/license review, AnkiWeb sync, a clean-target matrix and final release acceptance remain unfinished. No production release or tag should be published based on this workflow alone.

## Independent clean Ubuntu hosted-VM acceptance

After the release build uploads its candidate archive, CI downloads that artifact on a **second, independent Ubuntu 24.04 hosted VM** without checking out the source, and excludes Cargo from PATH during acceptance. The archived `scripts/test-clean-linux-candidate.sh` verifies the SHA256 sidecar, attribution and pinned source snapshots, installation and reinstallation, an actual X11 virtual-display GUI window, uninstall and preservation of private user data. This is independent *runtime* acceptance, not verification on every Linux distribution or a physical Wayland workstation. [Fresh hosted-VM replay 41498601466](https://github.com/sguzman/retivus/actions/runs/41498601466) proved this same archive acceptance passed before the release workflow adopted it. M6.4, M7.1 and final release criteria remain open.

## Runtime glibc baseline

Build the Linux x86_64 candidate on the fixed `ubuntu-24.04` host rather than the rolling `ubuntu-latest` image: a prior archive linked against GLIBC_2.43 and failed to launch on Debian 13 even though it passed its same-host GUI test. A separate Ubuntu 24.04 hosted VM checks the packaged binary on the 2.39 glibc baseline, without Cargo available. The portable-runtime check must pass before considering M7.2 complete; this still does not guarantee compatibility with older Linux systems or other architectures.

## X11 initial viewport visibility

An isolated Ubuntu 24.04 runtime showed an alive Retivus process with a fully created but **unmapped** initial X11 window. A diagnostic X11 `MapWindow` request caused the real egui UI to render, proving the problem was startup visibility rather than missing GLX or glibc compatibility. The native launch now explicitly requests a visible initial viewport; the release CI clean-runtime job must confirm mapping without external intervention before this gate can be accepted.

## Minimal container X11 limitation

A root-owned **and** an unprivileged-user `ubuntu:24.04` container running Openbox and Xvfb left the initial egui GL viewport unmapped, despite working llvmpipe and independently verified first-frame UI rendering after an external `MapWindow`. Waiting for Openbox registration and requesting an initial egui repaint did not change that container behavior. A **fresh, separate hosted Ubuntu VM** using the same checksummed candidate artifact passed the real mapped-GUI, install, update, uninstall and private-data preservation sequence; the rootless container issue remains recorded rather than being described as product-wide startup success. This test is not a substitute for physical Wayland and Orca acceptance.

## Same-commit binary and complete vendored-source pairing

The main Linux candidate workflow now invokes the [locked source audit](../.github/workflows/source-bundle-audit.yml) as a reusable workflow, retaining **two separate checksummed artifacts in the same run**: the installable binary candidate and a fully vendored offline Rust source candidate. A third job independently downloads both artifacts without a source checkout, verifies their checksums, compares their `Cargo.lock` bytes and SHA-256, requires matching exact Git commit provenance, and tests key pinned crates in the source archive. Passing this ensures *artifact pairing and source resolvability*, but does not certify that all applicable copyright/license notices or build requirements have undergone legal review. The release is still unpublished.

The same-commit parity check is implemented in `scripts/check-source-parity.sh` and independently exercised on the GitHub artifacts before CI integration. It also matches both source-license inventory files to the versions embedded in the checked source archive. This makes a mismatch or missing notice evidence an explicit failure rather than an undocumented assumption.
